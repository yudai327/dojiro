# 画面仕様

---

## 1. ページ構成

```
/                          ランディングページ（認証不要）
/login                     ログインページ（認証不要）
/dashboard                 ダッシュボード（認証必要）
/teams                     チーム一覧（認証必要）
/events                    イベント一覧（認証必要）
/matches/[id]/score        スコア入力画面（認証必要・adminのみ入力可）
```

### アクセス制御

| パス | 未認証アクセス |
|------|---------------|
| / | 許可（ランディングページを表示） |
| /login | 許可 |
| /dashboard | /login にリダイレクト |
| /teams | /login にリダイレクト |
| /events | /login にリダイレクト |
| /matches/[id]/score | /login にリダイレクト |

---

## 2. 共通仕様

### 認証トークンの保持

- ログイン後、JWTトークンを `localStorage` に保存する
- APIリクエスト時に `Authorization: Bearer <token>` ヘッダとして付与する
- ページアクセス制御は httpOnly Cookie `auth-token` で行う（サーバーサイドミドルウェア）

### 共通ヘッダー/ナビゲーション

現行実装では各ページが独立したヘッダー/ナビを持つ。将来的には共通レイアウトコンポーネントで統一する。

### エラーハンドリング

- API エラー（401, 403, 500）は画面上にエラーメッセージを表示する
- 401エラーは /login にリダイレクトする

## 3. ランディングページ `GET /`

### 目的

アプリの紹介・機能説明を行うページ。ログイン前の入口。

### 表示要素

- アプリ名「ドジロウ！」とサブタイトル
- アプリの説明テキスト
- 機能の紹介カード（スコア管理・イベント管理・チーム管理）
- CTA（Call To Action）ボタン
  - 未ログイン: 「ログイン」ボタン → /login
  - ログイン済み: 「ダッシュボードへ」ボタン → /dashboard

### インタラクション

- ログイン状態に応じてCTAボタンのリンク先が変わる
- ログイン状態の確認は localStorage のトークン有無で判定

---

## 4. ログインページ `GET /login`

### 目的

メールアドレスとパスワードでログインする。

### 表示要素

- メールアドレス入力フォーム
- パスワード入力フォーム
- ログインボタン
- エラーメッセージ表示エリア
- デモ用認証情報の表示（開発環境）

### フォームバリデーション

| フィールド | バリデーション |
|-----------|---------------|
| メールアドレス | 必須 |
| パスワード | 必須 |

### ログイン成功フロー

1. `POST /api/auth/login` にリクエスト
2. レスポンスの `token` を `localStorage` に保存
3. `/dashboard` にリダイレクト

### ログイン失敗フロー

1. エラーメッセージをフォーム下に表示（例: 「メールアドレスまたはパスワードが正しくありません」）

### 状態管理

| 状態 | 説明 |
|------|------|
| loading | ログインAPIリクエスト中。ボタンを無効化 |
| error | ログイン失敗時のエラーメッセージ |

## 5. ダッシュボード `GET /dashboard`

### 目的

アプリのメインハブ。主要機能への導線とサマリー情報を表示する。

### 表示要素

#### ヘッダー
- アプリ名
- ログアウトボタン

#### クイックアクションセクション
- 「イベント管理」ボタン → /events
- 「チーム管理」ボタン → /teams
- 「試合一覧」ボタン（将来実装）

#### イベント一覧（最大5件）
- `GET /api/events` から取得
- 各イベントのカード表示:
  - イベント名
  - 種別（tournament/practice/friendly）
  - 開始日〜終了日
  - 会場（あれば）

#### 試合一覧
- `GET /api/matches` から取得
- 各試合のカード表示:
  - 試合日・開始時刻・コート
  - ホームチーム名 vs アウェイチーム名
  - 所属イベント名
  - ステータス
  - 「スコア入力」ボタン → /matches/:id/score

### データロード

```
ページ初回表示時:
  1. localStorageからtokenを取得
  2. tokenがなければ /login にリダイレクト
  3. GET /api/events（Authorizationヘッダ付き）
  4. GET /api/matches（Authorizationヘッダ付き）
  5. 取得データを画面に反映
```

## 6. チーム一覧ページ `GET /teams`

### 目的

チームの一覧表示と新規チームの登録。

### 表示要素

#### ヘッダー
- ページタイトル「チーム管理」
- ナビゲーションリンク（ダッシュボードへ戻る）

#### チーム新規登録フォーム（adminのみ表示）

| フィールド | 入力タイプ | 備考 |
|-----------|-----------|------|
| チーム名 | テキスト | 必須 |
| カテゴリ | ドロップダウン | 選択肢: 男子 (men) / 女子 (women) / 混合 (mixed) |
| 所属組織 | テキスト | 任意 |

- 「チームを追加」ボタン → `POST /api/teams`
- フォームの表示/非表示をトグルボタンで切り替え

#### チームカード一覧

各チームを1枚のカードで表示:
- チーム名
- カテゴリ・所属組織
- 選手数（`players.length`）
- 選手リスト（最初の3名のみ表示。氏名と背番号）
- 「さらに表示」などのリンク（将来実装）

### データロード

```
ページ初回表示時:
  1. GET /api/teams → チームリスト（選手情報を含む）を取得
  2. 画面に反映
```

### フォーム送信フロー

1. バリデーション（チーム名が空でないか確認）
2. `POST /api/teams` にリクエスト
3. 成功: チームリストを再取得して表示を更新。フォームをリセット
4. 失敗: エラーメッセージを表示

## 7. イベント一覧ページ `GET /events`

### 目的

イベント（大会・練習会）の一覧表示と新規イベントの登録。

### 表示要素

#### ヘッダー
- ページタイトル「イベント管理」
- ナビゲーションリンク

#### イベント新規登録フォーム（adminのみ表示）

| フィールド | 入力タイプ | 備考 |
|-----------|-----------|------|
| イベント名 | テキスト | 必須 |
| 種別 | ドロップダウン | 選択肢: 大会 (tournament) / 練習試合 (practice) / 親善試合 (friendly) |
| 開始日 | 日付ピッカー | 任意 |
| 終了日 | 日付ピッカー | 任意 |

- イベント名
- 種別バッジ（tournament/practice/friendly）
- 開催期間（開始日〜終了日）
- 会場
- 備考

## 8. スコア入力ページ `GET /matches/:id/score`

### 目的

試合中にリアルタイムでプレーアクションを入力し、選手スタッツを即時確認する。

### 表示要素

#### ヘッダー
- 試合情報（チーム名 vs チーム名、日時、コート）
- ナビゲーションリンク

#### プレーアクション入力フォーム（adminのみ操作可）

**ステップ1: チーム選択**

| UI要素 | 説明 |
|--------|------|
| ラジオボタンまたはドロップダウン | ホームチーム / アウェイチームを選択 |

**ステップ2: 選手選択**

| UI要素 | 説明 |
|--------|------|
| ドロップダウン | 選択したチームの選手一覧（背番号 + 氏名で表示）。背番号昇順 |

**ステップ3: アクション種別選択**

| UI要素 | 説明 |
|--------|------|
| ボタングループ | アタック / キャッチ / カット |

**ステップ4: 結果選択**

| 選択されたアクション | UI要素 |
|---------------------|--------|
| attack または catch | 「成功」「失敗」ボタンを表示 |
| cut | 結果ボタンを非表示（常にsuccess固定） |

**記録ボタン**
- 「記録する」ボタン → `POST /api/matches/:id/player-actions`
- 記録後: フォームをリセット（チーム・選手・アクションをクリア）

#### フィードバックメッセージ

- 記録成功時: 「記録しました」などの成功メッセージ（2〜3秒後に消える）
- 記録失敗時: エラーメッセージ

#### スタッツテーブル

- `GET /api/matches/:id/stats` から取得して表示
- アクション記録後に自動で再取得・更新

**テーブル列:**

| 列 | 説明 |
|----|------|
| 選手名 | playerName |
| アタック成功 | attackSuccessCount |
| アタック失敗 | attackFailCount |
| アタック率 | attackRate（パーセント表示、小数第1位） |
| キャッチ成功 | catchSuccessCount |
| キャッチ失敗 | catchFailCount |
| カット | cutCount |
| キャッチ率 | catchRate（パーセント表示、小数第1位） |

### データロード

```
ページ初回表示時:
  1. GET /api/matches/:id → 試合情報（チーム・選手）を取得
  2. GET /api/matches/:id/stats → スタッツを取得
  3. 画面に反映

プレーアクション記録後:
  1. POST /api/matches/:id/player-actions
  2. 成功 → GET /api/matches/:id/stats を再取得してスタッツテーブルを更新
```

## 10. UIデザインガイドライン（現行実装）

現行実装のデザインはTailwind CSSによるユーティリティクラスを使用。再実装時の参考として記載。

### カラーパレット

| 用途 | 色系 |
|------|------|
| プライマリ（イベント・ナビ） | blue系 |
| チーム | green系 |
| スコア・選手 | purple系 |
| 試合 | orange系 |
| 成功メッセージ | green系 |
| エラーメッセージ | red系 |
| 管理者操作ボタン | indigo系 |

### レイアウト

- レスポンシブデザイン（モバイル〜デスクトップ対応）
- カードベースのUI（各エンティティをカードで表示）
- グリッドレイアウト（チーム一覧: 2〜3カラム、スタッツ: テーブル）
- フォームは初期非表示でボタンクリックで展開するパターンを使用

### ローディング状態

- データ取得中は「読み込み中...」などのプレースホルダーを表示
- ボタンはリクエスト中に無効化（連続送信防止）
